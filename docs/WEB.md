# Web — TanStack Start

Full-stack React app (SSR) built with [TanStack Start](https://tanstack.com/start), TanStack Router (file-based routing), TanStack Query and Tailwind CSS 4.
The structure follows Roy Portas' [*TanStack Start project structure*](https://royportas.com/posts/tanstack-start-project-structure).

## Structure

```
apps/web/
├── public/                     # static files (favicon…)
├── src/
│   ├── components/
│   │   ├── ui/                 # UI primitives (shadcn/ui conventions): button, input
│   │   ├── items/              # components of the "items" domain
│   │   ├── header.tsx          # components shared by several routes
│   │   ├── error-message.tsx
│   │   └── not-found.tsx
│   ├── hooks/                  # React hooks: use-item-mutations.ts
│   ├── lib/                    # non-UI helpers, data access
│   │   ├── api-client.ts       # fetch wrapper → NestJS API, ApiError
│   │   ├── items.ts            # endpoints, query keys, queryOptions
│   │   ├── query-client.ts     # TanStack Query configuration
│   │   ├── env.ts              # VITE_* variables
│   │   └── utils.ts            # cn()
│   ├── routes/
│   │   ├── __root.tsx          # HTML shell, header, devtools, global.css
│   │   ├── index.tsx           # /
│   │   ├── items/
│   │   │   ├── route.tsx       # layout of /items and its children
│   │   │   ├── index.tsx       # /items?page=n
│   │   │   └── $id.tsx         # /items/:id
│   │   └── $.tsx               # catch-all → 404
│   ├── global.css              # global styles + Tailwind theme
│   ├── router.tsx              # router creation + Query SSR integration
│   └── routeTree.gen.ts        # GENERATED, do not edit
├── vite.config.ts              # plugins: tanstackStart, nitro, tailwind, react
└── vitest.config.ts
```

### Routing rules

| File | Role |
|------|------|
| `__root.tsx` | Root: everything renders in its outlet. It holds the SSR HTML shell, providers, global navigation and the `global.css` import. |
| `folder/route.tsx` | Layout of the segment and its children (`items/route.tsx` wraps `/items/*`) |
| `index.tsx` | Page shown at the folder path (`items/index.tsx` → `/items`) |
| `_prefix/` | Layout **without a URL segment** (`_account/orders.tsx` → `/orders`) |
| `$param.tsx` | Dynamic segment (`$id.tsx` → `params.id`) |
| `robots[.]txt.ts` | Escaped dot: server route for `/robots.txt` |
| `$.tsx` | Catch-all, used here for the 404 page |
| `routeTree.gen.ts` | Generated by the Vite plugin (or `bun run generate-routes`), committed, never edited by hand |

### Difference from the article: no `src/db/`

The article puts the Drizzle client in `src/db/`. In Ember, **the database belongs to the NestJS API** (see [DATABASE.md](DATABASE.md)) and the front end never accesses it directly. That role is played by `lib/api-client.ts` and `lib/<domain>.ts`.

## Data flow

```
routes/items/index.tsx
  loader  ──▶ queryClient.ensureQueryData(itemsQueryOptions(page))   (server on first render, client afterwards)
  component ─▶ useSuspenseQuery(itemsQueryOptions(page))              (reads the hydrated cache)
             ─▶ useItemMutations()  ──▶ itemsApi.create / remove ──▶ invalidate ['items']
lib/items.ts ──▶ lib/api-client.ts (fetch) ──▶ NestJS /api/v1/items
```

- **Reads**: the route loader pre-fills the TanStack Query cache, so the SSR output already contains the data, with no loading flash.
- **Writes**: each mutation is declared in a hook in `hooks/` and invalidates the domain's query keys.
- **Errors**: `apiFetch` turns API errors into `ApiError` (with the server's status and message). The router shows `defaultErrorComponent`. A 404 or 400 on `/items/$id` triggers `notFound()`.

## Commands

```bash
bun run dev          # http://localhost:3001
bun run test         # Vitest + Testing Library
bun run lint         # ESLint (@tanstack/eslint-config)
bun run typecheck
bun run build        # client + Nitro server in .output/
bun run start        # node .output/server/index.mjs
```

Environment variable (see `.env.example`):

| Variable | Default | Description |
|----------|---------|-------------|
| `VITE_API_URL` | `http://localhost:3000/api/v1` | API URL, used by the browser and during SSR. It is inlined into the build. |

## Adding a feature

Example for `products`:

1. `lib/products.ts`: `productsApi`, `productKeys`, `productsQueryOptions`, typed with `import type { Product } from '@ember/contracts'` (the type is created in the contracts, not here)
2. `hooks/use-product-mutations.ts`
3. `components/products/`: domain components
4. `routes/products/route.tsx`, `index.tsx`, `$id.tsx` (loader + `useSuspenseQuery`)
5. A link in `components/header.tsx`
6. `*.test.ts(x)` tests next to the code
